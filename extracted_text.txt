MODULE 1: Lexical Analysis & Finite Automata
MODULE 1: Lexical Analysis & Finite Automata
The lexical analyzer (scanner) reads the raw characters of the source program and groups them
into tokens (keywords, identifiers, numbers, operators). Scanners are described with regular
expressions and implemented as finite automata. This module shows a LEX scanner, the
NFA-to-DFA conversion and a hand-written DFA.
1.1 LEX Program to Recognize Keywords, Identifiers,
Numbers and Operators
AIM Classify the characters of a source file into tokens: keywords, identifiers, numbers and
operators.
Algorithm (step by step)
1.Write the keyword rule before the identifier rule. When two rules match the same length, LEX
uses the one written first, so int becomes a KEYWORD, not an IDENTIFIER.
2.LEX always prefers the longest match, so interest is one IDENTIFIER, not the keyword int
followed by erest.
3.Count lines: every \n increases line_num.
4.Ignore white space and // comments (no action, no output).
5.Any other character is reported as UNKNOWN (a lexical error).

1.2 RE to NFA to DFA Conversion (Subset Construction)
AIM Convert an NFA into a DFA by subset construction and print the DFA state table. Example RE:
(a|b)*a (strings over {a, b} ending in a).
Algorithm (step by step)
1.ε-closure(S): all states reachable from the states in S using only ε-moves (including S itself).
2.Start state of the DFA = ε-closure({NFA start state}). Call it D0.
3.For each unprocessed DFA state T and each input symbol a: compute U = ε-closure(move(T,
a)).
4.If U is new, give it the next name (D1, D2, ...) and add it to the work list. Record the transition T
--a--> U.
5.Repeat until the work list is empty. A DFA state is accepting if it contains an NFA accepting
state.

How the code works
NFAState stores a name, a dictionary of transitions (symbol to list of next states) and an
accepting flag.
epsilon_closure uses a stack: pop a state, add every state reachable by ε, and keep going
until nothing new is found.
frozenset is used because normal sets cannot be dictionary keys, and every DFA state is a set
of NFA states.
The test NFA: s0 loops on a and b; on a it may also go to s1; s1 reaches the accepting s2 by ε. So
D1 = {s0, s1, s2} is accepting.
Reading the result: D0 --a--> D1, D0 --b--> D0, D1 --a--> D1, D1 --b--> D0. The DFA accepts a
string exactly when it ends in a.
VIVA TIP Steps to say in the viva: ε-closure, move, new state set, repeat; accepting if the set
contains an NFA final state.

1.3 C Program to Simulate a DFA (Valid Identifiers)
AIM Simulate a DFA that accepts identifiers matching [a-zA-Z_][a-zA-Z0-9_]*, with full input
validation.
Algorithm (step by step)
1.States: 0 = start, 1 = valid (accepting), -1 = dead (error).
2.In state 0: a letter or underscore moves to state 1; anything else moves to the dead state.
3.In state 1: a letter, digit or underscore stays in state 1; anything else moves to the dead state.
4.Empty input is rejected. After the last character the string is accepted only if the DFA is in state
1.

MODULE 2: Parsing Techniques & YACC
MODULE 2: Parsing Techniques & YACC
The parser checks that the token stream follows the grammar. Top-down parsers (recursive
descent, LL(1)) build the tree from the start symbol; bottom-up parsers (YACC / LALR(1)) build it
from the tokens upward.
2.1 Recursive Descent Parser for Arithmetic Expressions
AIM Write one C function per non-terminal to check whether an expression is valid. The grammar
(left recursion already removed): E -> T E' ; E' -> + T E' | ε ; T -> F T' ; T' -> * F T'
| ε ; F -> ( E ) | id.
Algorithm (step by step)
1.Make one function for each non-terminal: E, E', T, T', F. Each returns 1 (success) or 0 (failure).
2.Use the global pos as the lookahead; match a terminal by testing the character and doing
pos++.
3.For a rule with ε (E', T'), if the lookahead is not + / *, simply return 1 without consuming input.
4.The input is valid only if E() succeeds and the whole string was consumed (input[pos] ==
'\0').

2.3 LL(1) Table Generator (FIRST, FOLLOW and Parsing
Table)
AIM Compute the FIRST and FOLLOW sets programmatically and use them to build the LL(1)
parsing table for the expression grammar.
Algorithm (step by step)
1.FIRST: for a terminal a, FIRST(a) = {a}. For A -> X1 X2 ..., add FIRST(X1) minus ε; if X1 can
vanish also add FIRST(X2), and so on; if all can vanish add ε. Repeat until nothing changes.
2.FOLLOW: put $ in FOLLOW(start symbol). For A -> α B β, add FIRST(β) minus ε to FOLLOW(B). If
β can vanish (or is empty) add FOLLOW(A) to FOLLOW(B). Repeat until nothing changes.
3.Table: for each production A -> α: for every terminal a in FIRST(α) set M[A, a] = that
production. If ε is in FIRST(α), also set M[A, b] for every b in FOLLOW(A).
4.If any cell gets two productions, the grammar is not LL(1).

3.1 Infix to Postfix Conversion (Operator Stack)
AIM Translate an infix expression to postfix, with the correct precedence and with ^ (exponent)
being right-associative.
Algorithm (step by step)
1.Scan the expression from left to right.
2.Operand: append directly to the output.
3.'(': push on the stack. ')': pop to the output until '(' is found, then discard '('. If no '(' exists, the
parentheses are mismatched.
4.Operator: while the stack top is an operator with higher precedence (or equal precedence and
the new operator is left-associative), pop it to the output. Then push the new operator.
5.At the end pop everything to the output; a leftover '(' means mismatched parentheses.

3.3 Attribute-Based Type Checker for Assignments
AIM Use the type attributes of identifiers and constants to detect an invalid assignment such as a
float expression assigned to an int variable.
Algorithm (step by step)
1.Keep a symbol table that maps each variable to its declared type.
2.If the left-hand variable is not in the table, report an undeclared-variable error.
3.Compute the type attribute of the right side: start with int; if any variable is float or any

4.If the target is int and the expression is float, report a type error; otherwise the assignment is

4.1 Multi-Scope Symbol Table Manager
AIM Manage a stack of scopes: allow a name in an inner scope to hide (shadow) an outer one, but
reject a duplicate declaration in the same scope.
Algorithm (step by step)
1.Keep a list of dictionaries; index 0 is the global scope and the last one is the current scope.
2.enter_scope: push an empty dictionary. exit_scope: pop it (never remove the global scope).
3.insert: fail if the name already exists in the current scope; otherwise add it.
4.lookup: search from the innermost scope to the outermost and return the first match; return
None if absent.

5.1 Intermediate Code for Control Flow (if-else, while)
AIM Generate three-address code with labels and jumps for if-else and while statements.
Algorithm (step by step)
1.if (C) S1 else S2: test C; if false jump to the else label; run S1; jump to the end label; else
label: run S2; end label.
2.while (C) S: begin label; test C and jump to the end label if false; run S; jump back to the begin

5.2 Code Optimizer: Common Subexpression Elimination and
Dead Code Removal
AIM Remove repeated computations (CSE) and instructions whose results are never used (dead
code) from a block of three-address code.
Algorithm (step by step)
1.CSE (forward pass): remember each right-hand side already computed and the variable that
holds it. If the same expression appears again, do not emit it; remember that the new variable is
replaced by the old one.
2.Replace later uses of an eliminated variable by the variable that holds the value.
3.Dead code removal (backward pass): start with the set of variables needed after the block
(live_out). Walk the code from the last instruction to the first: keep an instruction only if its result
is live, and then make its operands live.
4.Everything else is dead and is dropped.

5.3 Assembly Code Generator (8086) for Arithmetic and
Procedure Calls
AIM Map three-address instructions to 8086 assembly and generate the code for a procedure call.

MODULE 6: Top 100 Viva-Voce Questions & Answers
MODULE 6: Top 100 Viva-Voce Questions &
Answers
Every answer is written in plain language. Short examples (yellow boxes) are given wherever they
make the idea easier to remember. Questions are grouped by topic but keep their original
numbers.
A. Compiler Basics & Phases
Q1.  What is a compiler?
A compiler is a program that reads a whole program written in a high-level language (like C)
and translates it into a low-level form such as machine code. It does this before the program
runs, and it reports errors it finds along the way. It usually works in several phases, not one
single step.
Example: gcc hello.c -o hello turns hello.c into the executable hello.
Q2.  Differentiate between a compiler and an interpreter.
A compiler translates the entire program first, produces a separate executable, and then the
executable runs fast. An interpreter translates and runs the program line by line, so there is
no separate executable and execution is usually slower. Compilers show all errors at once;
interpreters stop at the first error they reach.
Example: C uses a compiler; classic Python and JavaScript are interpreted (many modern ones mix
both).
Q3.  List the main phases of a compiler.
1) Lexical analysis - splits source text into tokens. 2) Syntax analysis - checks grammar
and builds a parse tree. 3) Semantic analysis - checks meaning (types, declarations). 4)
Intermediate code generation - produces machine-independent code such as
three-address code. 5) Code optimization - makes the code faster/smaller. 6) Target code
generation - produces assembly/machine code. The symbol table and error handler are used
by all phases.
Q4.  What is a lexeme, token and pattern?
A lexeme is the actual text in the source, e.g. count. A token is the category it belongs to,
e.g. IDENTIFIER. A pattern is the rule (usually a regular expression) that describes which
lexemes belong to a token.
Example: Lexeme count -> token IDENTIFIER -> pattern [a-zA-Z_][a-zA-Z0-9_]*.
Q5.  What is the output of the lexical analyzer?
A stream of tokens (each usually with an attribute such as the lexeme or a symbol-table
pointer). The parser asks for these tokens one at a time. Whitespace and comments are
removed by the lexer and never reach the parser.
Example: x = 5 + y; becomes ID(x) ASSIGN NUM(5) PLUS ID(y) SEMI.
B. LEX, YACC & Finite Automata
Q6.  What is FLEX?
Flex (Fast Lexical Analyzer Generator) is a tool that reads a specification file of regular
expressions with C actions (a .l file) and generates a C scanner (lex.yy.c). That scanner
contains the function yylex() which returns tokens. It is the modern, faster replacement for
the original Lex.

Q7.  What is YACC?
YACC (Yet Another Compiler-Compiler) is a parser generator. You give it grammar rules with C
actions (a .y file) and it generates a bottom-up LALR(1) parser in C (y.tab.c) with the
function yyparse(). GNU Bison is its free equivalent.
Q8.  What is a regular expression?
A regular expression (RE) is a compact notation to describe a set of strings. It is built from
characters and three operators: union |, concatenation, and Kleene star *. Scanners use REs
to describe tokens.
Example: [0-9]+ describes all unsigned integers; (a|b)*a describes strings over {a,b} ending in a.
Q9.  Define NFA and DFA.
A DFA (Deterministic Finite Automaton) has exactly one transition for each state and input
symbol and no ε-moves. An NFA (Nondeterministic) may have several transitions on the same
symbol and may have ε-moves (moves without reading input). Both recognize exactly the
same class of languages: regular languages. DFAs are faster to run; NFAs are easier to build
from REs.
Q10.  What is Thompson's construction?
An algorithm that converts a regular expression into an NFA with ε-transitions. It builds a small
NFA for each basic symbol and then combines them using fixed patterns for union,
concatenation and star. Every NFA it builds has one start state and one accepting state.
Q11.  What is subset construction?
The algorithm that converts an NFA into an equivalent DFA. Each DFA state is a set of NFA
states. Start with the ε-closure of the NFA start state; for each input symbol compute move
then ε-closure to get the next set; repeat until no new sets appear. A DFA state is accepting if
its set contains an NFA accepting state. (See program 1.2.)
Q12.  What is DFA minimization?
Reducing a DFA to the smallest equivalent DFA by merging states that behave identically
(indistinguishable states). First separate accepting from non-accepting states, then keep
splitting groups whose members go to different groups on some input. The result recognizes
the same language with fewer states, so the scanner is smaller.
C. Grammars & Parsing
Q13.  What is a context-free grammar (CFG)?
A CFG is a 4-tuple (V, T, P, S): V = non-terminals (syntactic variables), T = terminals
(tokens), P = production rules of the form A -> α, S = start symbol. Programming-language
syntax is described using CFGs.
Example: E -> E + E | id has V={E}, T={+, id}, S=E.
Q14.  What is an ambiguous grammar?
A grammar is ambiguous if at least one string has more than one parse tree (or leftmost
derivation). Ambiguity is a problem because the meaning of the program becomes unclear. It
is removed by rewriting the grammar or by giving precedence/associativity rules (as YACC
does with %left).
Example: E -> E + E | E * E | id gives two trees for id + id * id.

Q15.  What is left recursion?
A grammar is left-recursive when a non-terminal can derive a string that starts with itself, e.g.
A -> Aα | β. Direct left recursion appears in the rule itself; indirect left recursion appears
through a chain of rules.
Example: E -> E + T | T is left-recursive.
Q16.  Why must left recursion be eliminated for LL(1) parsing?
A top-down parser expands the leftmost non-terminal. With A -> Aα it expands A into A again
without consuming any input, so it loops forever. Rewrite A -> Aα | β as A -> βA' and A' ->
αA' | ε.
Example: E -> E+T | T becomes E -> T E', E' -> + T E' | ε (used in program 2.1).
Q17.  What is left factoring?
When two productions of a non-terminal start with the same prefix, the parser cannot choose
with one lookahead token. Left factoring pulls the common prefix out: A -> αβ1 | αβ2
becomes A -> αA', A' -> β1 | β2. The decision is postponed until the parser has read more
input.
Example: S -> if E then S | if E then S else S becomes S -> if E then S S', S' -> else
S | ε.
Q18.  What is the FIRST() set?
FIRST(α) is the set of terminals that can appear first in some string derived from α. If α can
derive the empty string, ε is also in FIRST(α). It tells a predictive parser which production to
pick for the next input token.
Example: For F -> ( E ) | id: FIRST(F) = { (, id }.
Q19.  What is the FOLLOW() set?
FOLLOW(A) is the set of terminals that can appear immediately after non-terminal A in
some sentential form. The end marker $ is in FOLLOW of the start symbol. FOLLOW is used
when a production can derive ε: the parser then uses FOLLOW(A) to decide when to choose
that production.
Example: In our expression grammar FOLLOW(E) = { $, ) }.
Q20.  What is an LL(1) parser?
A top-down predictive parser. First L: reads input Left to right. Second L: builds a Leftmost
derivation. The (1): uses one lookahead token to choose a production from the LL(1) table
M[non-terminal, terminal]. It needs a grammar with no left recursion, no common prefixes and
no ambiguity.
Q21.  What is an LR parser?
A bottom-up parser. L: reads input Left to right. R: builds a Rightmost derivation in reverse. It
repeatedly shifts input tokens onto a stack and reduces a handle on top of the stack to a
non-terminal, until only the start symbol remains. LR parsers handle a larger set of grammars
than LL parsers.
Q22.  Compare SLR(1), LALR(1) and CLR(1).
SLR(1): simplest; builds LR(0) item sets and uses FOLLOW sets to place reduce actions, so it
may report false conflicts. CLR(1) (canonical LR): items carry exact lookaheads; most
powerful but has the largest tables. LALR(1): merges CLR states that have the same core
(same items, different lookaheads); table size equals SLR but power is close to CLR. YACC
generates LALR(1).

Q23.  What is a shift-reduce conflict?
A state in the LR table where, for the same lookahead token, the parser could either shift the
token or reduce by a rule. It is usually caused by ambiguity. YACC resolves it using
precedence/associativity, or by default prefers shifting.
Example: The dangling-else problem: after if E then S seeing else, shift or reduce?
Q24.  What is a reduce-reduce conflict?
A state in which two or more different completed productions could be reduced for the same
lookahead. The parser cannot tell which one to use. YACC resolves it by choosing the rule that
appears first in the grammar file, but it is better to fix the grammar.
Q25.  What is Syntax-Directed Translation (SDT)?
A method of translating a program by attaching semantic rules or actions to the
productions of a grammar. These actions run while parsing and compute values such as
expression results, types or generated code.
Example: expr: expr '+' expr { $$ = $1 + $3; } in YACC.
D. Syntax-Directed Translation & Intermediate Code
Q26.  What are synthesized attributes?
Attributes of a parse-tree node that are computed from the attributes of its children.
Information flows upward (bottom-up).
Example: In E -> E1 + T, E.val = E1.val + T.val.
Q27.  What are inherited attributes?
Attributes of a node computed from its parent and/or left siblings. Information flows
downward or sideways. Useful for passing context such as a declared type.
Example: In D -> T L, L.type = T.type.
Q28.  Define S-attributed definitions.
An SDT that uses only synthesized attributes. It can be evaluated in one bottom-up pass, so
it fits naturally with LR parsers and YACC (the $$ = $1 ... style).
Q29.  Define L-attributed definitions.
An SDT in which each inherited attribute of a symbol on the right side depends only on the
attributes of the parent and of symbols to its left in the production. It can be evaluated in one
left-to-right depth-first pass, so it works with top-down (LL) parsing. Every S-attributed
definition is also L-attributed.
Q30.  What is intermediate code representation (ICR)?
A machine-independent form of the program produced between the front end and the back
end. It is easier to optimize than source code and easier to translate than machine code.
Common forms: syntax trees, postfix, three-address code. It lets one front end work with
many back ends.
Q31.  What is three-address code (TAC)?
An intermediate code in which every instruction has at most three addresses: typically one
result and two operands, with at most one operator on the right side.
Example: a + b * c becomes t1 = b * c, t2 = a + t1.

Q32.  Compare quadruples and triples.
A quadruple has four fields (op, arg1, arg2, result) and stores the result name explicitly, so
instructions can be moved easily during optimization. A triple has three fields (op, arg1,
arg2); a result is referred to by the position of the instruction, which saves space but makes
reordering hard.
Example: t1 = b * c as quadruple: (*, b, c, t1); as triple (0): (*, b, c).
E. Type Checking, Symbol Tables & Run-time Memory
Q33.  What is static type checking?
Checking types at compile time, before the program runs, so type errors (like assigning a
float expression to an int variable, or adding a string to a number) are reported early.
Languages such as C and Java do this.
Q34.  What is type coercion?
Implicit (automatic) conversion of a value from one type to another by the compiler, usually to
a wider type so no information is lost.
Example: In float f = 3 + 2.5; the int 3 is automatically converted to 3.0.
Q35.  What is a symbol table?
A data structure used by all compiler phases to store information about identifiers: name,
type, scope, memory offset, number/types of parameters, etc. The lexer/parser insert entries
and later phases look them up.
Q36.  What data structures are used for symbol tables?
Hash table (most common: average O(1) lookup), binary search tree (O(log n), keeps
names sorted) and linked list (simple but O(n) lookup, fine for tiny programs).
Q37.  How are nested scopes managed in a symbol table?
With a stack of tables (one per scope). On entering a block a new empty table is pushed; on
leaving it is popped. A lookup searches from the innermost table outwards, so inner names
hide (shadow) outer names. (See program 4.1.) This is lexical (static) scoping.
Q38.  What is an activation record?
The block of memory (stack frame) created for each procedure call. It holds the parameters,
return address, saved registers, local variables, temporaries, and the control (dynamic) and
access (static) links. It is pushed on call and popped on return.
Q39.  What is a dynamic (control) link?
A pointer stored in an activation record that points to the activation record of the caller.
Following it lets the program return to the caller's frame.
Q40.  What is a static (access) link?
A pointer stored in an activation record that points to the activation record of the procedure in
which the current procedure is lexically nested. It is used to access non-local variables in
languages that allow nested procedures (e.g. Pascal).
Q41.  Define heap allocation.
Run-time allocation of memory from a large pool (the heap) for data whose lifetime does not
follow procedure calls. It stays until freed explicitly (or by garbage collection).
Example: malloc() in C and new in C++/Java.
F. Optimization & Code Generation

Q42.  What is a basic block?
A maximal sequence of consecutive instructions with one entry (only the first instruction can
be jumped to) and one exit (control leaves only at the last instruction). If the first instruction
runs, all instructions in the block run.
Q43.  What is a control flow graph (CFG)?
A directed graph whose nodes are basic blocks and whose edges show possible flow of control
(jumps and fall-through). It is used for optimization and loop detection. (Do not confuse with a
context-free grammar, which has the same abbreviation.)
Q44.  What is code optimization?
Transforming code so it runs faster or uses less memory without changing its meaning
(output must remain the same).
Q45.  What is common subexpression elimination (CSE)?
If an expression has already been computed and its operands have not changed, reuse the
earlier result instead of recomputing.
Example: t1 = a + b ... t3 = a + b: replace uses of t3 by t1.
Q46.  What is dead code removal?
Deleting instructions whose results are never used (dead code), or that can never execute
(unreachable code). It shrinks and speeds up the program.
Example: unused = x + 1 when 'unused' is never read.
Q47.  What is constant folding?
Evaluating expressions whose operands are all constants at compile time, so the work is not
repeated at run time.
Example: x = 3 * 7; becomes x = 21;.
Q48.  What is constant propagation?
Replacing a variable by its known constant value in later statements. It often creates new
chances for constant folding.
Example: n = 5; y = n * 2; becomes y = 5 * 2; then y = 10;.
Q49.  What is loop-invariant code motion?
Moving a computation whose value does not change inside the loop to just before the loop
(the pre-header), so it is calculated once instead of every iteration.
Example: while(i<n) x = a*b + i;: compute t = a*b before the loop.
Q50.  What is strength reduction?
Replacing an expensive operation with an equivalent cheaper one.
Example: x * 2 becomes x + x or x << 1; multiplication by loop index becomes repeated addition.
Q51.  Define peephole optimization.
Looking at a small sliding window (the 'peephole') of target instructions and replacing it by a
shorter or faster sequence. It removes redundant loads/stores, jumps to jumps, and useless
instructions.
Example: MOV R0,a then MOV a,R0 - the second instruction is redundant.
Q52.  What is register allocation?
Deciding which program variables and temporaries are kept in the limited CPU registers at
each point of the program. Registers are much faster than memory, so good allocation speeds
up the code a lot.

Q53.  What is graph coloring in register allocation?
Variables are nodes in an interference graph; two nodes are joined if the variables are live at
the same time. The graph is colored with K colors (K = number of registers) so that
connected nodes get different colors. Each color becomes a register. If K colors are not
enough, some variables are spilled to memory.
Q54.  What is a cross compiler?
A compiler that runs on one machine (host) but generates code for a different machine
(target).
Example: Compiling on a PC to produce code for an ARM microcontroller.
Q55.  What is bootstrapping?
Writing a compiler for a language in the same language, using a simple earlier version (often
hand-compiled or written in another language) to compile the first full version. After that the
compiler can compile itself.
Example: Many C compilers are written in C.
G. LEX / YACC Internals
Q56.  What is the role of yyin in Lex?
yyin is the global FILE * from which the scanner reads input. By default it is stdin; set yyin
= fopen("file", "r"); to scan a file (see program 1.1).
Q57.  What is yytext in Lex?
yytext is a character pointer (char *) to the text of the lexeme that was just matched. Its
length is in yyleng. Copy it if you need it after the next call to yylex().
Q58.  What is yylval in YACC?
A global variable that carries the semantic value of a token from the lexer to the parser. The
lexer sets yylval = atoi(yytext); and returns NUMBER; in the grammar the value is read
as $1, $2, ...
Q59.  What does yywrap() do?
The scanner calls yywrap() when it reaches end of input. If it returns 1, scanning stops. If it
returns 0, the scanner continues with another input file (which you must set up). Most
programs simply return 1 (or use %option noyywrap).
Q60.  How are precedence rules specified in YACC?
With %left, %right and %nonassoc in the declarations section. Operators listed on later lines
have higher precedence; operators on the same line have equal precedence.
Example: %left '+' '-' then %left '*' '/': * and / bind tighter than + and -.
H. More Concepts (Parsing, Optimization, Errors, Tools)
Q61.  What is an Abstract Syntax Tree (AST)?
A condensed tree showing the structure of the program, with operators as internal nodes and
operands as children. Unlike a parse tree it leaves out grammar details such as parentheses,
semicolons and chain rules.
Example: a + b * c: root +, children a and (* with children b, c).

Q62.  What is backpatching?
A technique to generate code for jumps in one pass. When a jump is generated its target is
not yet known, so it is left blank and added to a list; later, when the target label is known, all
jumps in that list are filled in (patched).
Example: In an if-statement the jump past the 'then' part is patched after the 'then' code is
generated.
Q63.  What is a DAG representation?
A Directed Acyclic Graph of a basic block in which each distinct expression or value appears
once. A node with several parents is a common subexpression, so the DAG helps find CSE and
dead code.
Q64.  Differentiate between top-down and bottom-up parsing.
Top-down starts at the start symbol and expands non-terminals to match the input (leftmost
derivation) - e.g. recursive descent and LL(1). Bottom-up starts from the input tokens and
reduces them to the start symbol (reverse rightmost derivation) - e.g. SLR, LALR, CLR.
Bottom-up handles more grammars; top-down is simpler to write by hand.
Q65.  What is a handle in shift-reduce parsing?
A substring of the current right-sentential form that matches the right side of a production,
and whose replacement by the left side is one step of the reverse rightmost derivation.
Finding the handle tells the parser when to reduce.
Q66.  What is a viable prefix?
A prefix of a right-sentential form that can appear on the stack of a shift-reduce parser (it
does not extend past the right end of the handle). As long as the stack holds a viable prefix,
no error has been detected yet.
Q67.  Name a feature that is not context-free.
Checking that a variable is declared before it is used (and that types match) cannot be
expressed in a CFG. It needs context, so it is done in semantic analysis with a symbol table.
Q68.  What is type conversion?
Changing a value of one type into another. Implicit conversion (coercion) is done by the
compiler; explicit conversion (casting) is requested by the programmer.
Example: (float) i is an explicit cast.
Q69.  What is a symbol-table entry offset?
The relative address of a variable within its activation record (or data area), e.g. 'x is at offset
4'. The compiler assigns offsets using the sizes of the types, and the generated code accesses
the variable as base + offset.
Q70.  What is a calling sequence?
The code executed at a procedure call: the caller evaluates and pushes arguments, saves the
return address and jumps to the procedure; the callee then allocates its frame and saves
registers.
Example: PUSH y; PUSH x; CALL swap; ADD SP, 4 (program 5.3).
Q71.  What is a return sequence?
The code executed when a procedure ends: place the return value, restore saved registers,
free (pop) the activation record and jump back to the saved return address.
Q72.  What is copy propagation?
After a copy statement x = y, later uses of x are replaced by y (while neither changes). The
copy may then become dead code and be removed.

Q73.  What is loop unrolling?
Repeating the loop body several times inside the loop so that fewer iterations (and fewer
test-and-jump instructions) are needed. It makes code faster but larger.
Example: A loop of 100 iterations can be unrolled by 4 to become 25 iterations of a body with 4
copies.
Q74.  What is loop fusion?
Combining two adjacent loops that run over the same range into one loop, which reduces loop
overhead and often improves cache use.
Q75.  What is instruction selection?
Choosing the target-machine instructions that implement each piece of intermediate code,
preferring the fastest or shortest sequence. A machine may have many ways to do the same
job.
Example: x = x + 1 may use INC x instead of load, add, store.
Q76.  What is instruction scheduling?
Reordering instructions (without changing the result) to avoid pipeline stalls, for example by
placing independent instructions between an instruction that loads a value and the one that
uses it.
Q77.  What is spill code?
Extra load/store instructions that save a register's value into memory and bring it back later,
used when there are more live variables than registers.
Q78.  What is machine-independent optimization?
Optimization applied to the intermediate code that does not depend on the target CPU.
Example: Constant folding, CSE, dead-code removal, loop-invariant motion.
Q79.  What is machine-dependent optimization?
Optimization that uses details of the target machine such as its registers, instruction set and
pipeline.
Example: Register allocation, peephole optimization, instruction scheduling.
Q80.  What is a lexical error?
An error found by the scanner when the characters cannot form any valid token. Typical
examples are an illegal character or a malformed number or identifier.
Example: The character @ in C source, or the identifier 9abc.
Q81.  What is panic mode recovery?
An error-recovery method: after an error the parser throws away input tokens until it finds a
synchronizing token (like ; or }) and then continues. It is simple and never loops forever,
but may skip many tokens.
Q82.  What is phrase-level recovery?
After an error the parser makes a local correction on the remaining input, such as inserting
a missing semicolon or deleting an extra comma, so that parsing can continue.
Q83.  What is a syntax error?
An error where the sequence of tokens does not follow the grammar. It is detected by the
parser.
Example: A missing semicolon or unbalanced parenthesis: x = (a + b;.

Q84.  What is a semantic error?
An error in a program that is grammatically correct but breaks the meaning rules of the
language, such as type or scope rules. It is detected in semantic analysis.
Example: Using an undeclared variable, or assigning a float expression to an int variable (program
3.3).
Q85.  What is an intermediate code tree?
A tree form of intermediate code in which operators are internal nodes and operands are
leaves; the code generator walks the tree to produce target instructions. It is a
machine-independent representation similar to an AST.
Q86.  What is a linker?
A tool that combines one or more object files and library routines into one executable,
resolving references between them (for example a call to printf) and assigning final
addresses.
Q87.  What is a loader?
The part of the operating system that copies an executable into main memory, sets up its
address space and starts execution. If needed it relocates addresses.
Q88.  What is symbol-table offsetting?
Computing the memory offset of each variable by adding the sizes of the previously declared
variables. The offset is stored in the symbol table.
Example: With int=4, float=4, char=1: int a; char b; float c; have offsets 0, 4 and 5 (or 8 if
aligned to a 4-byte boundary).
Q89.  What is a type environment?
A mapping from identifiers to their types that the type checker uses while checking each
expression or statement. It is essentially the symbol table seen from the type checker's side.
Example: {x: int, y: float, z: int} in program 3.3.
Q90.  What is operator-precedence parsing?
A simple bottom-up shift-reduce method for operator grammars (no ε-productions and no two
adjacent non-terminals on a right side). It uses a table of precedence relations (less than,
equal, greater than) between operators to decide when to shift or reduce.
Q91.  Differentiate front end and back end.
Front end (lexical, syntax, semantic analysis, intermediate code) depends on the source
language. Back end (optimization and code generation) depends on the target machine.
Separating them lets m languages and n machines be supported with m + n parts instead of
m x n compilers.
Q92.  What is an indirect triple?
A listing of pointers to triples: the program is a list of pointers, each pointing to a triple in a
separate table. To reorder instructions only the pointer list is rearranged, so the triples need
not be changed.
Q93.  What is a non-terminal symbol?
A syntactic variable in a grammar. It represents a set of strings and appears on the left side of
productions. It is expanded using productions until only terminals remain.
Example: E, T and F in the expression grammar.

Q94.  What is a terminal symbol?
A basic symbol (token) of the language that cannot be broken down further by the grammar.
Terminals appear in the final strings.
Example: +, *, (, ), id.
Q95.  What is a start symbol?
The special non-terminal from which every valid string of the language is derived. It is
normally the left side of the first production.
Example: E in the expression grammar.
Q96.  What is a regular grammar?
A grammar in which every production has the form A -> aB or A -> a (right-linear; the
left-linear form is also regular). It generates exactly the regular languages (Type 3), the same
languages that regular expressions and finite automata describe.
Q97.  Describe the Chomsky hierarchy level for compilers.
The hierarchy has four types: Type 0 (unrestricted), Type 1 (context-sensitive), Type 2
(context-free) and Type 3 (regular). Scanners use Type 3 (regular expressions / finite
automata); parsers use Type 2 (context-free grammars / pushdown automata).
Q98.  What is run-time storage management?
How the program's memory is organized and used while it runs. It is divided into: Code (the
instructions), Static data (globals, constants), Stack (activation records of procedure calls)
and Heap (dynamically allocated data).
Q99.  What is a register interference graph (RIG)?
A graph used in register allocation. Each node is a variable (or temporary); an edge joins two
variables that are live at the same time and therefore cannot share a register. Coloring the
graph assigns registers (see question 53).
Q100.  Why is compiler design fundamental to computer science?
Compilers connect human-friendly programming languages with the machine hardware, so
every program we write depends on one. Compiler design combines automata theory,
grammars, data structures, algorithms and computer architecture, and its ideas are reused in
interpreters, text tools, query languages and many other areas.
